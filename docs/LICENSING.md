# Licensing

Droidwire's own source code is licensed under the **MIT License** (`LICENSE`, (c) 2026 Ajith M Jose). MIT covers only that code. The release builds also contain third-party programs and libraries under their **own** licenses; they are not MIT, and this document says exactly which are shipped and what each requires. It is not legal advice.

The machine-generated, exact-to-the-build tables are in [third-party-inventory.md](third-party-inventory.md); the full texts ship inside the app as `THIRD-PARTY-LICENSES.txt` (generated by `scripts/license-inventory.mjs`) next to the summary `THIRD-PARTY-NOTICES.md`, `ELECTRON-LICENSE.txt` and `LICENSES.chromium.html`, and are shown in the app under Droidwire > Licenses.

### Why adb is built from source (the "ADB question")

- Google's **prebuilt** `platform-tools` binaries are downloaded under the **Android SDK License Agreement** (the download page requires accepting it: https://developer.android.com/tools/releases/platform-tools). Its section 3.4 states "You may not copy (except for backup purposes), modify, adapt, redistribute, decompile, reverse engineer, disassemble, or create derivative works of the SDK or any part of the SDK" (https://developer.android.com/studio/terms). Droidwire therefore does **not** redistribute that binary, and does not infer permission from other applications that bundle adb.
- The adb **source code** in AOSP is licensed Apache-2.0: "Apache 2.0 is the preferred license for AOSP, and the majority of Android software is licensed with Apache 2.0" (https://source.android.com/docs/setup/about/licenses). Apache-2.0 permits redistributing a binary built from it, provided the license and notices accompany it.
- Droidwire builds adb from AOSP source using the Apache-2.0 [android-tools](https://github.com/nmeum/android-tools) release tarball for `platform-tools-37.0.0` (SHA-256 pinned), and ships the Apache-2.0 notices. The Android SDK License does not apply to a binary the project built itself from the Apache-licensed source. If you doubt that reading, the remaining choices are to ask Google for written permission to redistribute their binary, or to stop bundling adb; do not switch back to bundling Google's binary on the strength of other apps doing it.

## 2. Artwork, fonts and assets

- **Logo / icon / DMG art / `site/og-image.png`**: derived from the Android robot ("bugdroid"). Google allows reproduction and modification under **Creative Commons Attribution 3.0** and requires the line *"The Android robot is reproduced or modified from work created and shared by Google and used according to terms described in the Creative Commons 3.0 Attribution License."* It also forbids claiming trademark rights in the robot or derivatives, requires "Android is a trademark of Google LLC" wherever the name is used, and says app names should read "X for Android", not "Android X" (https://developer.android.com/distribute/marketing-tools/brand-guidelines). The attribution is in the README, the app notices and the site.
- **Name**: "Droidwire" contains "Droid", a word other companies have used as a trademark. Whether that matters for this name is a legal question for the owner (flagged in the release notes); no conclusion is drawn here.
- **Fonts**: none are bundled or downloaded; the UI names Inter, then falls back to system fonts.
- **UI icons**: inline SVG written for this project.
- No tracked image contains personal information (checked visually).

## 3. luck-node-mtp: attribution gap

`luck-node-mtp` (author field: "lucksoft") declares `"license": "ISC"` in its `package.json`, but its repository (https://github.com/lucksoft-yungui/luck-node-mtp, last commit 2023-08-18) has **no LICENSE file and no copyright holder or year**. ISC requires the copyright notice and permission text to be kept; with no upstream notice that cannot be done verbatim. What Droidwire does about it:

- `THIRD-PARTY-LICENSES.txt` includes the standard ISC text with the copyright line "Copyright (c) lucksoft" - the author named in the package metadata - and says in terms that upstream publishes no license file or year and that no year is claimed.
- Residual risk, stated plainly: without a license file in the upstream repository, the ISC grant rests on a one-line metadata field. Droidwire also modifies the code (the patch in `patches/`).
- Recommended follow-up (owner): ask the upstream author to add a LICENSE file (suggested text: `docs/release-prep/upstream-luck-node-mtp-issue.md`; **not posted anywhere**), and consider replacing the addon with an in-house binding to libmtp if that does not arrive.
